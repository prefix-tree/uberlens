# UberLens: research on the sources

Every source `docs/design.md` leans on exists, and the overall architecture survives being checked against them, but many details in the design came from a project brief rather than the papers, and those details are often wrong. **OmniAgent** is arXiv:2606.19341 (Xing et al., ICML 2026, Apache-2.0). Its tools take only `start/end(/num)` arguments, return raw media (not transcripts), and "consolidate" memory by having the acting model write an `observation` field while the environment purges older media. **ActiveForager** is arXiv:2611.24267 (Li et al., Nov 2026). It confirms the 4-frame 224² window and the Answer/ZoomIn/Recall/Wait action set, but its EvidenceCard is smaller than ours, it allows one tool call per query, it adds an evidence gate and an attention mask (SDAM) that the design leaves out, its RL algorithm is a GRPO variant called TUPO rather than GSPO, and **its repository has no license, so its code must not be copied**. **ForeSeek** is arXiv:2611.26024 (Tencent, MIT). It keeps one expectation at a time, not one per interval, skims 10–20 uniform frames rather than splitting at scene cuts, has no neighbour-propagation or "top-HIGH refuted" re-plan rule, penalises rounds rather than frames, and its "2.5–4.4× fewer frames" claim is measured against one agent (EVA), not search agents in general. **Gemini Decision 1** and **AnyS1** are both real and point to the same System-1 recipe: score the options in one pass, include a "none of the above" option, and fit a threshold per decision point in shadow mode instead of using a flat τ = 0.7. The benchmarks are real but all non-commercial and not redistributable, and the design's offline set leaves out LVBench and VideoHolmes, the benchmarks on which the papers it copies actually report. The report closes with numbered edits to design.md, split into factual corrections, things to adopt, and UberLens extensions that must be labelled and ablated.

## How these sources were checked and what stays unverified

The findings rest on five research notes. Each source was checked against its primary paper, and where a public repository exists, against the repository at a pinned commit. OmniAgent was read from the arXiv v2 HTML and the repo at commit `0ce93ec` ([arXiv](https://arxiv.org/html/2606.19341); [GitHub](https://github.com/harryhsing/OmniAgent)). ActiveForager was read from the v2 PDF and the repo at `47131fe` ([arXiv PDF](https://arxiv.org/pdf/2611.24267v2); [GitHub](https://github.com/TiezMind/ActiveForager)). ForeSeek was read from the v1 HTML and the repo at `a2181317` ([arXiv](https://arxiv.org/html/2611.26024); [GitHub](https://github.com/harry0021/ForeSeek)). AnyS1, JevAgentHarness and "Fast Models, Slow Evidence" were read in full ([AnyS1](https://arxiv.org/html/2611.23751); [JevAgentHarness](https://arxiv.org/html/2610.21412v1); [Fast Models, Slow Evidence](https://arxiv.org/abs/2610.02267)). Benchmark facts come from the official GitHub repos.

Three areas are only partly verified, and the report marks them **[unverified]** where they come up. First, Gemini Decision 1: blog.google, ai.google.dev and aistudio.google.com could not be fetched, so its details come from search excerpts of Google's posts and API reference plus secondary coverage. Second, every Hugging Face page was unreachable, so the licenses of model weights and datasets are unchecked. Third, the benchmark sizes, which were usually confirmed from READMEs rather than papers. The classic cascade papers (FrugalGPT, RouteLLM, AutoMix, SwiftSage) are cited from their abstracts and were not re-read.

## OmniAgent: native tools, raw media, self-written memory

**Identity.** The paper is "Native Active Perception as Reasoning for Omni-Modal Understanding", arXiv:2606.19341, by Zhenghao Xing, Ruiyang Xu and others from CUHK, SJTU and Alibaba's Qwen team, accepted at ICML 2026 ([arXiv](https://arxiv.org/abs/2606.19341); [GitHub README](https://github.com/harryhsing/OmniAgent)). It is **not** the December 2025 "OmniAgent: Audio-Guided Active Perception Agent" (arXiv:2512.23646), an inference-only tool-orchestration agent ([arXiv](https://arxiv.org/html/2512.23646v1)). The design cites "OmniAgent" with no ID, so the two are easy to confuse.

**Loop and state.** OmniAgent treats the task as a POMDP and runs an Observation–Thought–Action (OTA) cycle. On each turn one native omni model emits a single line of JSON, `{"observation", "think", "confidence", "action"}`, and **`confidence` (0–1) is required on every turn**, not only on the answer. The prompt's "0.9 rule" allows answering only when confidence ≥ 0.9, except when a `[NOTICE] FINAL STEP` message forces an answer ([video_prompt.py](https://github.com/harryhsing/OmniAgent/blob/main/agent_system/environments/prompts/video_prompt.py)). The state is the chat history and nothing more: the META message (duration, fps, has_audio) plus the question, then each turn's JSON. There is no structured memory list, no belief map and no retrieval index ([arXiv §3.1, Alg. 1](https://arxiv.org/html/2606.19341)).

**Memory consolidation is not a separate summarizer.** The acting model distils the latest percept into its own `observation` field. After every step the environment calls `_replace_old_media(keep_count=1)`, which rewrites each earlier media message as a placeholder that keeps the evidence header and the exact frame timestamps, for example `Frames 10.00s-12.00s (num=5). Timestamps: [...] [MEDIA OMITTED - Refer to your Observation]`. As a result, only the latest percept carries pixels or audio ([video_env.py](https://github.com/harryhsing/OmniAgent/blob/main/agent_system/environments/env_package/video_env.py); [arXiv App. B.4](https://arxiv.org/html/2606.19341)). The prompt asks for an "exhaustive, high-fidelity log", with evidence-ID prefixes and [y, x] grid IDs for counted objects. It also asks the model to scan wide first and then bisect, never to repeat an identical action, to re-inspect through another modality, and to look actively for counter-evidence ([video_prompt.py](https://github.com/harryhsing/OmniAgent/blob/main/agent_system/environments/prompts/video_prompt.py)).

**Tools.** None of the four tools takes a resolution or fps argument, and none returns text.

| Tool | Exact schema | Returns | Default cap |
| --- | --- | --- | --- |
| `get_frames` | `{start, end, num}` | JPEGs at source resolution from `linspace(start, end, num)`, endpoints included | 60 frames |
| `get_audio` | `{start, end}` | raw mono 16 kHz WAV; the model transcribes it itself | 300 s |
| `get_clip` | `{start, end}` | mp4 with an AAC audio track, sampled by the Qwen-Omni processor | 60 s, at least 4 frames |
| `answer` | `{content}` | a letter for MCQ, `[[s,e],...]` for temporal grounding, a number, or free text | — |

The caps are the evaluation defaults; the evaluation turn limit is `min(5 + int(duration/60), 32)` ([omniagent_eval.py](https://github.com/harryhsing/OmniAgent/blob/main/demo/omniagent_eval.py); [video_env.py](https://github.com/harryhsing/OmniAgent/blob/main/agent_system/environments/env_package/video_env.py)). The Qwen processor caps visual tokens at 1,024 per image and 768 per video frame, within a 64K context ([arXiv §4.1](https://arxiv.org/html/2606.19341)). Invalid actions return structured errors such as `Err.TS_OOB`, which the agent is meant to correct on its next turn ([arXiv App. B.3](https://arxiv.org/html/2606.19341)).

**Training.** The base model is Qwen2.5-Omni-7B. Stage one is agentic SFT on **58K trajectories** produced by best-of-N exploration with a Gemini-3-Pro teacher. Trajectories that recover from errors are kept, and a two-stage filter is applied: outcome verification (exact match; IoU ≥ 0.5; MRA ≥ 0.5), then a GPT-4o "rationality audit" requiring at least 3/5. The SFT run is a full fine-tune with frozen encoders, lr 1e-5, 2 epochs, batch 64. Per-episode budgets are randomized during synthesis: 30–60 frames, 30–60 s clips and 150–300 s audio ([arXiv §3.2, §4.1](https://arxiv.org/html/2606.19341); [sft_agent_final.yaml](https://github.com/harryhsing/OmniAgent/blob/main/recipe/sft_agent_final.yaml)). Stage two is RL with **TAURA**, a GRPO variant. The per-turn advantage is A_i·w_{i,k}, where w is the turn's mean token entropy divided by the group mean. It is trained DAPO-style (clip 0.20/0.30, no KL, no entropy bonus) for 150 steps with G = 8 and lr 1e-6, only on queries where best-of-N failed and only on videos under 300 s. Rewards are rule-based: exact match, IoU or MRA. There is **no format or turn penalty** ([arXiv Eqs. 2–6](https://arxiv.org/html/2606.19341); [train_TAURA.sh](https://github.com/harryhsing/OmniAgent/blob/main/examples/omniagent_train/train_TAURA.sh)).

**Results.** Agentic SFT does most of the work. The ablation table gives LVBench 43.0 → 48.7 from SFT, then 50.5 after TAURA ([arXiv Table 4](https://arxiv.org/html/2606.19341)). Against its base model, OmniAgent-7B scores 59.6 vs 54.8 on VideoMME-Long, 50.5 vs 43.0 on LVBench and 71.1 vs 65.2 on MLVU. It beats Qwen2.5-VL-72B on LVBench with about 203 frames instead of 768, but still trails Gemini-2.5-Pro, which scores 67.4 there ([GitHub README](https://github.com/harryhsing/OmniAgent); [arXiv Table 1](https://arxiv.org/html/2606.19341)). Turns grow only from 8.5 to 12.5 across 20- to 140-minute videos. Wall-clock time is 66.8 s per LVBench question on one A100, of which about 10 s is ffmpeg extraction ([arXiv Tables 5, 7](https://arxiv.org/html/2606.19341)).

**Code and license.** The code, the gym-style OTA environment and the SFT recipe are released under **Apache-2.0**. Checkpoints are published as `harryhsing/OmniAgent-RL-7B` and `-SFT-7B` (their weight license is **[unverified]**). The repo also includes a Gemini harness that runs closed models in the same environment. The 58K trajectories were not found to be released ([GitHub README](https://github.com/harryhsing/OmniAgent)).

## ActiveForager: a four-way router with a gated sub-agent

**Identity.** The paper is "Look Closer, Look Back, or Wait for Agentic Streaming Video Understanding", arXiv:2611.24267, v1 posted 18 Nov 2026 and v2 on 19 Nov 2026. The authors are Pengyu Li, Zhitao Gao, Lingling Zhang and others, mostly at Xi'an Jiaotong University ([arXiv API](https://export.arxiv.org/api/query?id_list=2611.24267)). The arXiv metadata abstract ("47.6% → 65.9%") does not match any table in v2. Use the v2 PDF numbers instead ([paper p.1](https://arxiv.org/pdf/2611.24267v2)).

**State.** The GPU working context holds exactly **w = 4 frames at 224², sampled at 1 fps**, about 255.5 visual tokens after 2×2 patch merging, plus a header giving stream time and frame count. A 672² base window is the second regime they report ([paper §4.1, §B.2](https://arxiv.org/pdf/2611.24267v2)). Two CPU stores sit behind the window:

- a **high-res ring buffer** holding the last 4.0 s at 896² and 10 fps, which feeds ZoomIn;
- a **visual-only archive** of evicted frames. Frames are described by 3×3-grid RGB histograms plus gradient statistics, and a new segment starts when 1 − cos > 0.20 or the segment reaches 10 s. The archive holds at most 256 segments and evicts the oldest first; each segment stores its time span, peak change score and frame pointers. **No captions and no text are stored** ([paper §B.2, Table 9](https://arxiv.org/pdf/2611.24267v2)).

**Actions and schemas.** After a short diagnostic rationale the policy picks one of {Answer, ZoomIn, Recall, Wait}. The released code's output format is `<think>…</think>` followed by exactly one action tag ([protocol.py](https://github.com/TiezMind/ActiveForager/blob/47131feb8539c314623b180340b20f8a8ee6a7cb/forager/protocol.py)):

| Action | Payload | Behaviour |
| --- | --- | --- |
| ZoomIn | `{"mode": "spatial_hires"\|"temporal_hifps", "roi": [x1,y1,x2,y2] in [0,1], "window_sec": 2.0}` | a hi-res crop (448² on 7B, 672² on 8B, in the 224² regime) or a 4-fps burst taken from the ring buffer |
| Recall | `{"query", "lookback_sec": 60.0, "top_k": 2}`, optional `start_sec`, `end_sec` | ranks segments by query match + 0.15·peak change + 0.25·temporal overlap; a time range reweights the ranking rather than filtering it; candidates must be ≥ 2 s apart |
| Wait | `{"check_after_sec": 1.0, "trigger"}` | advances the stream and re-runs routing; at most 5 waits, then the agent must answer |
| Answer | text | returns the answer from the recent window |

Recall runs the **same VLM weights in a separate context with a clean KV cache**, which verifies representative frames and returns an **EvidenceCard**. The card holds a status (Found/None), an anchor timestamp, a factual note of at most 64 tokens (the code asks for at most 25 words) and, when Found, one anchor frame of 64 tokens. **A None card passes zero historical visual tokens** to the main agent; the paper calls this the evidence gate ([paper §4.2, §B.5](https://arxiv.org/pdf/2611.24267v2)). **SDAM** is an additive attention mask in the synthesis turn. It stops recent-frame tokens and evidence tokens from attending to each other at every layer, and after a Found Recall the answer tokens cannot attend to the recent frames ([paper §4.2, Eq. 2](https://arxiv.org/pdf/2611.24267v2)). After a ZoomIn or Recall the agent must answer, so tools never chain. Each question is answered once.

**Control.** Algorithm 1 accepts a direct Answer only when its confidence p_max ≥ τ_conf, which is **0.68 for the 7B model and 0.80 for the 8B**, both chosen on a 60-item validation split. A low-confidence Answer is escalated to the highest-logit tool. Calibration alone is worth +2.4 and +1.7 points ([paper Alg. 1, Tables 8–9](https://arxiv.org/pdf/2611.24267v2)). Clue-reveal (CRR) questions also use a Yes/No readiness log-odds rule at evaluation ([paper §B.4](https://arxiv.org/pdf/2611.24267v2)). The released code adds keyword rules that the paper does not describe, for example "always Recall if an 'Unable to answer' option exists" ([agent.py](https://github.com/TiezMind/ActiveForager/blob/47131feb8539c314623b180340b20f8a8ee6a7cb/forager/agent.py)). Whether the reported numbers used those rules is **[unverified]**.

**Training (TUPO).** Training starts with SFT on 6,000 trajectories: 2.0k Answer, 1.8k ZoomIn, 1.6k Recall and 0.6k Wait, with cross-video negatives supervising None cards. RL then uses a GRPO variant. The reward is R = R_acc (−0.5 when wrong) + 0.65·R_IG + 0.20·R_fmt − 0.03·C, where C is a normalized visual-token cost. The tool-utility term is R_IG = V_act · 1[correct] · clip(ΔI, 0, 1). ΔI is the **per-token log-likelihood gain of the gold answer under a frozen reference model** with versus without the evidence; for Wait, it compares the window after waiting with the window before. V_act is a deterministic check that the rationale matches the action. Advantages are group-mean-centred without std normalization (Dr. GRPO style), and the loss weights each turn equally. Training also uses **balanced context perturbations**, each applied to a whole group: clean with probability 0.28, and 112², one-frame or premature contexts at 0.24 each. Hyperparameters are LoRA r = 32, α = 64, frozen ViT, AdamW lr 2e-6, batch 32, G = 8, 300 steps, clip 0.2 and β_KL = 0.02 ([paper §4.3, §B.1–B.3, Table 9](https://arxiv.org/pdf/2611.24267v2)). Removing R_IG kills ZoomIn on 7B (12.26% → 0.00%) and costs 4.7 points overall ([paper Table 4](https://arxiv.org/pdf/2611.24267v2)). **The released RL script builds its rollouts from templated trajectories rather than on-policy samples**, so the equations, not the script, are the reference ([train_ig_grpo.py](https://github.com/TiezMind/ActiveForager/blob/47131feb8539c314623b180340b20f8a8ee6a7cb/scripts/train_ig_grpo.py)).

**Results.** On OVO-Bench (the paper uses 1,640 queries across 12 subtasks), the best configuration, Qwen3-VL-8B at 672², scores **71.30 overall with 2,354 main-context visual tokens**, against 70.29 and 6,559 tokens for StreamScout-R. At the 224² budget, TUPO lifts the SimpleStream-4f baseline by about 10–11 points while using roughly 295–409 tokens ([paper Table 1](https://arxiv.org/pdf/2611.24267v2)). The ablations show what each piece buys:

- **The evidence gate drives hallucination detection.** HLD rises from 73.12 with an ungated card to 93.55 with the gate, and to 99.46 with both gate and SDAM ([paper Table 3](https://arxiv.org/pdf/2611.24267v2)).
- **Learned Wait beats fixed delays.** FAR is 50.65 with learned Wait against about 35–36 for fixed delays ([paper Table 8B](https://arxiv.org/pdf/2611.24267v2)).
- **Latency is 357–1,264 ms per query** on one GPU with 16–20 GB of memory ([paper Table 7](https://arxiv.org/pdf/2611.24267v2)).

One internal inconsistency: the bootstrap-CI footnote for the 672² gains (+3.04 and +1.01) does not match Table 1 (+16.33 and +9.31), so treat the 672² comparisons with caution.

**Code and license.** The training, evaluation, data-manifest and mock-test code is public, but **no weights are released and there is no LICENSE file**, and `pyproject.toml` declares none ([pyproject.toml](https://github.com/TiezMind/ActiveForager/blob/47131feb8539c314623b180340b20f8a8ee6a7cb/pyproject.toml)). Without a license, all rights are reserved by default. UberLens engineers may read the code but must not copy it; reimplement from the paper's equations.

## ForeSeek: one expectation, a label belief, and a round-decay reward

**Identity.** The paper is "ForeSeek: Foresight-Driven Reasoning for Long-Form Video Understanding", arXiv:2611.26024, v1 posted 19 Nov 2026, by Yuchen Sun and others at Tencent PCG and CSIG. Its code is MIT-licensed ([arXiv abs](https://arxiv.org/abs/2611.26024); [LICENSE](https://github.com/harry0021/ForeSeek/blob/main/LICENSE)).

**State.** The state is the triple S_r = (B_r, φ_r, H_<r): a global interval belief, **one expectation φ_r for the current target interval**, and the reasoning trace. B_r is a list of (start, end, relevance, hint) entries, with relevance drawn from **{High, Medium, Low, Elim}** and no probabilities. Medium is the default "no signal" label, Low marks a weak prior or a failed search, and Elim is a hard exclusion the model declares after verification ([arXiv Eq. 2](https://arxiv.org/html/2611.26024)). Initialization is a uniform scan of N(T) = clip(round(10 + 3·log2(1 + T/600)), 10, 20) frames, after which the model writes B_1 and φ_1 in one call. The intervals are the **gaps between probe frames, not scene cuts**. The released code uses a linear N instead, `min(20, max(10, 10 + T/300))` ([arXiv Eq. 1](https://arxiv.org/html/2611.26024); [foresight_agent_v9k2.py](https://github.com/harry0021/ForeSeek/blob/main/Code/foresight_agent_v9k2.py)). Frames are resized to 0.8× resolution. The code does not enforce a partition, and re-emitted intervals overwrite earlier ones.

**Loop and schemas.** Each round samples n_r ∈ [4, 16] frames, chosen by the model, uniformly from the search interval. The same policy then produces a verdict in {confirmed, partially confirmed, not found} and either answers or emits a new prediction, a search interval with a frame count, and belief updates ([arXiv §Method](https://arxiv.org/html/2611.26024)). The code's output format is `<verification>Expected: … Actual: … Result: …</verification>` followed by either `<answer>X</answer>` or `<prediction>…</prediction><search>[s-e] frames=N</search><intervals>[s-e] relevance=… scene_hint=<3-5 words></intervals>`. Each round is a fresh VLM call: earlier frames are not re-sent, and only a text history of the predict→verify chain carries over ([prompts_v9k2.py](https://github.com/harry0021/ForeSeek/blob/main/Code/prompts_v9k2.py)). The run stops when the model answers or at **R_max = 5** rounds, where an answer is forced. After RL the agent averages **about 2 rounds**. The loop uses video only: no audio, no subtitles and no other tools ([arXiv Eq. 5, Table 6](https://arxiv.org/html/2611.26024)).

**Negative evidence.** The model relabels intervals itself. A thin scheduler ranks High above Medium, excludes Low and Elim (using Low only as a fallback), and after a failed search demotes the interval to Low but never to Elim ([arXiv §Global Interval-level Belief](https://arxiv.org/html/2611.26024)). There is **no neighbour propagation and no separate global re-plan step**, because every round can rewrite the belief. Prediction–verification beats a reactive search agent trained the same way only after RL (VideoMME 61.1 vs 58.1); after SFT alone, the results are "mixed" ([arXiv App. A.2, §Analysis](https://arxiv.org/html/2611.26024)). The authors acknowledge an efficiency–recall trade-off when they demote an interval after a single sparse look.

**Training.** The base model is Qwen3-VL-8B (replicated on Qwen2.5-VL-7B), trained with full parameters on 8×H20 GPUs. SFT uses **8,165 trajectories** written by a Gemini-3-Flash teacher. The teacher first makes a deployment-faithful Phase-1 call, then an oracle call that sees the ground truth and dense frames; the SFT run is 1 epoch at lr 2e-6. RL uses **GSPO** on 4,663 questions filtered to pass@8 ∈ [1, 6], with lr 1e-6, G = 8, ε clip 1e-3/1.5e-3 and k1 KL β = 0.02. The reward is **R = R_ans · T(n)**, where T = 1.0 for fewer than 4 rounds, 0.9 at 4 and 0.8 at 5. The decay is multiplicative and applies only to correct answers, and **there is no frame penalty** ([arXiv §Stage 2, Alg. 1](https://arxiv.org/html/2611.26024); [v9k2_reward.py](https://github.com/harry0021/ForeSeek/blob/main/Code/v9k2_reward.py)).

**Results.** ForeSeek-GSPO scores 61.1 on VideoMME, 60.1 on LongVideoBench, 40.3 on LVBench, 53.2 on VideoHolmes and 66.2 on MLVU, using 22–31 frames per question. The "2.5–4.4× fewer frames" claim is the ratio against **EVA** (arXiv:2603.22918, a Qwen2.5-VL-7B agent): ForeSeek matches or beats EVA on 3 of the 5 benchmarks and trails by at most 3 points on the other two ([arXiv Table 1](https://arxiv.org/html/2611.26024)). All evaluation runs without subtitles, on the full Video-MME rather than only its long split. Total frames grow only 1.34× from short to long videos, and **the frame budget does not grow with uncertainty**, a weakness UberLens can target ([arXiv §Analysis (c)](https://arxiv.org/html/2611.26024)). Absolute LVBench accuracy (40%) sits far below GPT-5 and VideoSeek (60–68%), so the win is efficiency at 8B, not frontier accuracy.

**Code and license.** The agent, prompts, trajectory builder, VeRL GSPO launchers and evaluation harness are MIT-licensed. Weights (`Harry0021/ForeSeek`) and data (`Harry0021/ForeSeek-Data`) are on Hugging Face under licenses that are **[unverified]** ([README](https://github.com/harry0021/ForeSeek)). The paper and the code disagree on the Phase-1 formula, the evaluation frame cap (16 vs 64) and the number of RL epochs (1 vs 3); follow the paper when reproducing it.

## System-1: Gemini Decision 1, AnyS1 and the cascade literature

**Gemini Decision 1 is real.** It is a non-generative model, `gemini-decision-1`, behind the Gemini Decisions API, launched around 11 November 2026 as an AI Studio preview. In one pass it answers up to 1,000 closed questions about a shared multimodal input that can include text, images, **audio, video** or PDF. Each question is binary, a single-select choice, or a rubric score with 2–255 levels, and the API returns per-option probabilities. It charges **$0.10 per 1M input tokens and bills no output tokens** ([Google on Threads](https://www.threads.com/@google/post/DfnJDdWm4ph); [API reference](https://aistudio.google.com/api-reference/decisions?hl=ja); [DataCamp](https://www.datacamp.com/blog/gemini-decision-1)). Binary answers are clipped to 0.01–0.99 **[unverified, secondary]** ([Flavio Copes](https://flaviocopes.com/gemini-decisions-api/)). Google's own claims are a Top-1 ECE of 0.025 and 150–250 ms end to end ([36Kr](https://eu.36kr.com/en/p/4065770698331011)). One independent field test measured a **p95 latency of 1,131 ms and an ECE of 0.072 on real data**, against 0.020 on synthetic data ([switch PR #2126](https://github.com/sandbox-quantum/switch/pull/2126)). No model card, request schema or details on rate limits, fine-tuning or logit access were seen **[unverified]**.

**AnyS1 is real.** The paper is "Thinking Fast, Anywhere: One System-1 for the Decision Points of Any Agent Workflow", arXiv:2611.23751, by Li, He, Huang and Liu (USTC) with Zhang (NTU), released under CC BY 4.0 ([arXiv](https://arxiv.org/html/2611.23751)). It sorts workflow steps into deterministic (D), generative (G) and enumerable (E) nodes. An E node has a question, options with one-sentence definitions, and **"none of the above"**. The model is a 4B pointer model on Qwen3.5-4B-Base with rank-16 LoRA. A permutation-equivariant head scores all options in **one forward pass**, and the model is trained with label smoothing on 25,986 examples mined from 1,072 skills. The gate delegates to System-1 only when max p ≥ τ, where τ is the smallest threshold reaching **95% agreement with System-2**. The threshold is fitted either "cold" (153 held-out examples) or "warm" (50 unlabeled episodes run with System-2 while System-1 scores in the background). With the gate, episode cost falls 87–89%; most of that comes from compiling skills into D/E/G programs, and System-1 adds about 8 points of saving. **Without the gate, ALFWorld success collapses from 95.5 to 40.3**. One τ does not transfer across workflows, but 20 development episodes are enough to fit one. Label smoothing gives an ECE of 0.094, against 0.146 for hard-label cross-entropy ([AnyS1 §3–4, Tables 2–5](https://arxiv.org/html/2611.23751)). The code (`middle-chunjie/AnyS1`) and weights (`smSquirrel/AnyS1-4B`) have **unchecked licenses**, and the model is text-only.

**Related 2026 work agrees.** JevAgentHarness (arXiv:2610.21412) has three findings that matter here. The model best on isolated questions solved only 69.5% of tasks in the loop. A fixed threshold of 0.5 lost 21.5 points. Thresholds fitted per decision point on shadow trajectories, using a cost rule that weighs the price of the saved call against the cost of a wrong choice, came out near **0.99–1.00**, saved 14.2% and changed none of 500 task outcomes. All 34 of its failed tasks began with an **irreversible** wrong choice ([JevAgentHarness](https://arxiv.org/html/2610.21412v1)). "Fast Models, Slow Evidence" (arXiv:2610.02267) found option-order sensitivity, with 30% of answers flipping when options were reversed. Its self-audit also showed how savings get overstated: leaving out System-1's cost on deferred calls inflated a 4.3% saving to 23.9%, and in-sample thresholds missed a 5% target by up to 17% on held-out data ([arXiv](https://arxiv.org/abs/2610.02267)). The classic background is consistent with this, from the abstracts. FrugalGPT and RouteLLM fit cascades and routers to cost thresholds ([FrugalGPT](https://arxiv.org/abs/2305.05176); [RouteLLM](https://arxiv.org/abs/2406.18665)). Temperature scaling fixes overconfidence without changing the argmax ([Guo et al.](https://arxiv.org/abs/1706.04599)). Verbalized confidence tends to be overconfident ([Xiong et al.](https://arxiv.org/abs/2306.13063)). LLMs show option-position bias ([Zheng et al.](https://arxiv.org/abs/2309.03882)). Selective classification should be judged on risk–coverage curves ([Geifman & El-Yaniv](https://arxiv.org/abs/1705.08500)). **No published System-1 evaluation exists for video decision points** such as which interval to inspect or whether visual evidence is sufficient. UberLens's savings could therefore be smaller than AnyS1's.

### (b) Things to adopt from the papers

25. **§3 Recall, evidence gate.** A `None` card passes **zero** historical visual tokens to the main context. This is the largest single factor on false-premise questions (HLD 73 → 94). Source: [ActiveForager Table 3](https://arxiv.org/pdf/2611.24267v2).
26. **§5 SDAM substitute.** API models do not expose attention masks. After a Found Recall, answer from the evidence plus the text context without the recent frames; otherwise keep recent frames and evidence in separate calls. Label this an approximation of SDAM and ablate it. Source: [ActiveForager §4.2](https://arxiv.org/pdf/2611.24267v2).
27. **§2/§3 consolidation, the OmniAgent way.** Keep only the latest percept's media (keep_count = 1). Replace older media with placeholders that keep the evidence ID and exact timestamps. Require the evidence-ID prefix in memory text (it maps onto `MemoryEntry.span`) and [y, x] grid IDs for counting. Source: [video_env.py](https://github.com/harryhsing/OmniAgent/blob/main/agent_system/environments/env_package/video_env.py); [video_prompt.py](https://github.com/harryhsing/OmniAgent/blob/main/agent_system/environments/prompts/video_prompt.py).
28. **§3 environment feedback.** Add `[NOTICE] Step k/K` and `FINAL STEP` messages, and structured `[ERROR]` codes such as `TS_OOB` and `INVALID_JSON` that the agent can recover from. Source: [OmniAgent App. B.3](https://arxiv.org/html/2606.19341).
29. **§3/§4 prompt rules.** Never repeat an identical action on the same range; re-inspect through another modality or at a higher density instead. Scan wide, then bisect. After a not-found, make a *different* prediction. Never predict absence. Sources: [OmniAgent prompt](https://github.com/harryhsing/OmniAgent/blob/main/agent_system/environments/prompts/video_prompt.py); [ForeSeek prompts](https://github.com/harry0021/ForeSeek/blob/main/Code/prompts_v9k2.py).
30. **§5 router calibration baseline.** Accept a direct Answer only when p_max ≥ τ_conf (0.68 for 7B, 0.80 for 8B, fitted on about 60 validation items); otherwise take the highest-scoring tool. Use this as the streaming System-1 baseline. Add the CRR readiness log-odds rule for clue-reveal questions. Source: [ActiveForager Alg. 1, §B.4](https://arxiv.org/pdf/2611.24267v2).
31. **§6 `DecisionPoint`/`Decision`.** Add a `NONE` option to every point, a one-sentence definition per option, and an `irreversible` flag. Add the fields `decided_by`, `escalated`, `threshold_used`, `margin`, `latency_ms`, `cost`, and `s1_scores` kept even when System-2 decides. Treat `NONE` as an escalation, or as a trigger to re-propose options. Source: [AnyS1 §3.1](https://arxiv.org/html/2611.23751).
32. **§6 confidence source.** Replace "small model prompted for JSON with per-option scores" with this order of preference: (1) a single-pass scorer, either Gemini Decision 1 for multimodal points or an AnyS1/Jev-style pointer model for text-only points; (2) option-token log-probabilities averaged over 2–3 option permutations; (3) verbalized JSON only as a last resort. Sources: [AnyS1](https://arxiv.org/html/2611.23751); [Xiong et al.](https://arxiv.org/abs/2306.13063); [Zheng et al.](https://arxiv.org/abs/2309.03882).
33. **§6 thresholds.** Replace "τ starts at 0.7" with per-point thresholds fitted in **shadow mode**: in at least 20 development episodes (AnyS1 used 50), System-2 decides every point while System-1 scores in the background. Pick the smallest τ that reaches 95% agreement with System-2, or use JevAgentHarness's cost rule. Fit on some episodes and check on held-out ones. Refit whenever a model, prompt or option set changes. Keep 0.7 only as the heuristic backend's default before any data exists. Sources: [AnyS1 §3.3, §4.5](https://arxiv.org/html/2611.23751); [JevAgentHarness §2.1](https://arxiv.org/html/2610.21412v1); [Fast Models, Slow Evidence](https://arxiv.org/abs/2610.02267).
34. **§6 irreversible points.** `stream_action = answer` and `sufficient = yes` both end the episode, so give both a stricter τ. `next_interval` is long-horizon search, where ungated System-1 collapsed in AnyS1's ALFWorld test. Shortlist its candidates, give each a one-line description, and keep margin-based escalation. Thresholds for binary Gemini Decision 1 questions must stay below 0.99 because of clipping **[unverified]**. Sources: [AnyS1 Table 3a](https://arxiv.org/html/2611.23751); [JevAgentHarness §7.5](https://arxiv.org/html/2610.21412v1).
35. **§6/§7 batching and backend.** Add Gemini Decision 1 as a `DecisionModel` backend. Ask `verify_expectation`, `sufficient` and `observe_how` in one request over the same frames, so the input is billed once. Budget against p95 latency (about 1.1 s measured), not the median. Source: [API reference](https://aistudio.google.com/api-reference/decisions?hl=ja); [switch PR #2126](https://github.com/sandbox-quantum/switch/pull/2126).
36. **§6 calibration.** Apply per-backend temperature scaling on logged decisions, and label smoothing (ε ≈ 0.1) for trained or distilled models. Report ECE and risk–coverage AURC per point. Sources: [Guo et al.](https://arxiv.org/abs/1706.04599); [AnyS1 Table 3c](https://arxiv.org/html/2611.23751).
37. **§8 budget defaults.** OmniAgent defaults: at most 60 frames per `get_frames`, 300 s per `get_audio`, 60 s per `get_clip`, and a step limit of min(5 + duration/60, 32). ForeSeek defaults: 10–20 skim frames, 4–16 frames per round, at most 5 rounds. ActiveForager defaults: one tool per query, at most 5 waits. **Count System-1 calls, including deferred ones,** in cost and time. Sources: [OmniAgent](https://github.com/harryhsing/OmniAgent); [ForeSeek](https://arxiv.org/html/2611.26024); [Fast Models, Slow Evidence](https://arxiv.org/abs/2610.02267).

## Conclusion

The papers change the design's centre of gravity more than its outline. All three agents do most of their reasoning inside one generation per turn, with small, fixed interfaces: OmniAgent's four tools with two or three numbers each, ForeSeek's four labels and single expectation, ActiveForager's single tool per query and gated card. They get their efficiency from training (agentic SFT in particular) and from discipline about what enters the context, not from orchestration layers. UberLens's distinctive bets are the System-1/System-2 split, the explicit partitioned belief, structured memory and repeated proactive answers. None of these is supported by the agent papers, and the System-1 literature warns that savings shrink once in-loop success, deferred-call cost and irreversible steps are counted. Each therefore needs to earn its place against faithful reproductions of the source agents, which the MIT and Apache code make cheap to build.

The one gap no source fills is a calibrated System-1 for *video* decisions: which interval to look at next, which modality to use, and whether the evidence so far is enough. That is where UberLens could contribute something new, and its shadow-mode decision logs are the dataset for it. The constraint to plan around is licensing rather than technique. ActiveForager must be reimplemented from scratch, and every public benchmark is non-commercial, so a product claim about UberScene or Cutleap footage will need an in-house, timestamped evaluation set from the start.

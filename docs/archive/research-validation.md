# UberLens: research on the validation tasks (R01–R13)

The direction the user chose, doing VIVID's job through UberScene's typed, video-as-code timeline, survives this research, but as an open empirical question and no longer as a novelty claim. Both halves are already published separately: VIVID has the on-demand looking, version-pinned evidence and render review and leaves editing to agent-written FFmpeg ([VIVID](https://arxiv.org/html/2611.20688)), and Cassette-Editor (arXiv:2610.37690, October 2026) is a typed, validated, undoable, revision-checked timeline harness with ablations ([Cassette-Editor](https://arxiv.org/html/2610.37690)). Nobody has combined them or run the 2×2 of perception tools on/off × typed timeline vs FFmpeg on one model on a long-source editing benchmark; that 2×2, with a third edit-path arm for free-form TSX text editing, is **the single most valuable experiment**. What survives on evidence is small and mostly not UberLens's own: a transcript and shot layer built once, bounded on-demand looks, code checks, a look at the render, task files, an expected-revision check and a code gate with rollback. What should be dropped from the agent's loop or put behind an experiment is most of what the design marks "ours": claim kinds and eligibility, per-decision pass state with declared dependencies, the activity-placed overview, the belief scheduler, model-set sampling density and 1–5 craft scores. None of these targets a failure anyone has demonstrated, and the nearest published evidence points against several of them. The UberScene code audit also found that the bridge is a choice, not a requirement: UberScene's own agent skill tells agents to edit the TSX as text, and that is the baseline typed actions must beat. Several of these conclusions are the researchers' inferences from adjacent fields (question answering, code agents), and they are marked as such below; the editing-practice notes (R03, R07, practice side of R08) rest on search snippets only.

Background verified earlier is cited by filename and not repeated: `docs/research.md` (perception papers), `docs/research-editing.md` (editing agents, VIVID, AgenticVBench), `docs/research-importance.md` (frame selectors), `docs/research-rres.md` (SAVE, residual-risk review, Timeline-Bench). The design under challenge is `docs/design.md`, fifth version.

## 1. Verdict: what survives, what goes, and the experiment that decides the direction

**What this research does to the "VIVID through UberScene" direction.** It keeps the direction and changes its claim. Three statements the direction rests on are weaker than the design says. First, "a harness whose edits go through a typed, undoable timeline" is prior art: Cassette-Editor has schema-derived typed patches, a 110-rule rulebook, atomic commits, undo with branches and refusal of a patch based on a stale version ([Cassette-Editor](https://arxiv.org/html/2610.37690)); RefineCut trains a planner that edits a typed timeline through verifier-checked patches ([RefineCut](https://arxiv.org/abs/2608.25622), abstract only); Cutible is an MIT tool with a diffable JSON timeline, undo and branch, and Remotion TSX generation ([Cutible README](https://raw.githubusercontent.com/plokdalberb-byte/cutible/main/README.md)). Second, "video as code for agents" is not new either: Timeline-Bench's agent container already ships Remotion and HyperFrames with a headless browser ([Timeline-Bench §4.1](https://arxiv.org/html/2609.35143v1)). Third, "cheap re-rendering" is narrower than it sounds: UberScene's frame cache feeds only `look` and `--still`, never a full export, and a CPU export runs at about 6 frames a second at 1080p for a file with a three.js scene (`/home/user/cutcraft/packages/render/src/cli.ts:357, 454`; `docs/guide/exporting.md:61-62`; code audit, nothing was run). What is cheap is looking at the cut without rendering it, and a partial render with `--from/--to --draft`.

What remains open, and worth owning, is the comparison nobody has run. VIVID shows perception and review add about 20 points with FFmpeg editing (Codex 38.4 → 58.6) ([VIVID Table 1](https://arxiv.org/html/2611.20688)). Cassette-Editor shows a typed timeline passes 92/93 request checks against 48/93 for basic tools, but inside its own editor, on two finished 3-minute projects, with self-written requests, and "no run inspected rendered video" ([Cassette-Editor](https://arxiv.org/html/2610.37690)). Whether the typed edit path adds anything on top of VIVID-style perception on long raw sources is unmeasured. So is whether typed actions beat an agent freely editing the same TSX file as text.

**Survives on evidence** (and is mostly available without UberLens): the transcript and shot layer built once before the agent starts; bounded on-demand frames, crops and audio (−16.0 points when removed from VIVID); code checks before any taste judgment; a look at the render (−14.6 when removed); task state in plain files; an expected-revision precondition; a code check of approved ranges with rollback ([VIVID Table 2](https://arxiv.org/html/2611.20688); [regression study](https://arxiv.org/html/2607.01855v1)).

**Drop from the agent's loop or demote to an experiment:** claim kinds, eligibility and required verdicts (keep harness-written observations as a log, add an independent check); global and per-decision pass state with `depends_on` (replace with versioned sections, computed diffs and a gate); agent-set burst interval and frame count (harness sets density from span width); passes as an enforced state machine (keep as vocabulary); activity prior and belief scheduler (experiments only); 1–5 craft scores from the critic (yes/no items tied to the segment's purpose, and code-computed pacing checks first).

**The single most valuable experiment:** one model, AgenticVBench (and Timeline-Bench if access is granted), four cells: perception tools {off, on} × edit path {agent-written FFmpeg, UberScene}. The UberScene column is split in two so the result separates "video as code" from "typed actions": (i) the agent edits `video.tsx` as text with UberScene's own skill, (ii) the agent edits through the typed-action bridge. Matched budgets, several runs per task. It answers the direction question directly, and no published result does.

## 3. R01: the minimal baseline is untested, and it already solves compliance

**Finding.** Two benchmarks bracket the baseline that design.md section 1.1 names, and neither runs it. On AgenticVBench, native agents with no prepared transcript or index and a 30-minute, 4-vCPU limit score 38.4 (GPT-5.6-sol + Codex), 32.4 (Claude Fable 5 + Claude Code) and 27.4 (GPT-5.5 + OpenCode) against 88.5 for experts; VIVID lifts the same three to 58.6, 55.1 and 37.1 ([VIVID Table 1](https://arxiv.org/html/2611.20688)). On Timeline-Bench, with a `transcribe` command, Remotion and HyperFrames installed and 300 minutes, **857 of 863 delivered videos meet the delivery spec and 762 pass every brief test, yet only 14.0% of 896 runs resolve**, and 562 of 771 failures fail only the quality test ([Timeline-Bench §5–6, App. J.1](https://arxiv.org/html/2609.35143)). A different harness or a 1,909-word editing skill changed nothing significantly there (15 vs 12 resolved, p = 1.00) ([Timeline-Bench Table 9](https://arxiv.org/html/2609.35143)). A dedicated editing harness is not automatically better: GPT-5.6-sol inside Crayotter's environment scores 33.7, below native Codex ([VIVID Table 1](https://arxiv.org/html/2611.20688)).

The failures VIVID fixes are failures of the bare agent under a tight clock. Drowning, 83% of failed Repurpose runs, is defined as spending the budget on whole-source transcription or thumbnailing ([AgenticVBench §3.2](https://arxiv.org/html/2605.27705)); a transcript built before the clock starts plausibly removes it with no harness at all. The researcher calls this "the single most important untested claim for UberLens", and it is an inference: the only supporting datum is that prepending an editor's scene notes added 23 points on one hard Repurpose task ([AgenticVBench §3.4](https://arxiv.org/html/2605.27705)). VIVID's ablation carries a caveat too: every variant with one component removed still beats native Codex, and the "memory" ablation removes the evidence store together with the task files, with `retrieve` called in only 10–32% of tasks ([VIVID Table 2, §5.1](https://arxiv.org/html/2611.20688)).

### Deliverable: baseline architecture

The strongest setup that needs no new harness (researcher's synthesis; every piece exists under a permissive licence, licences mostly read from listings, not LICENSE files):

| Layer | Contents |
| --- | --- |
| Ingest by code, before the agent starts, cached per file | `ffprobe` inventory; word-timed transcript with speakers (WhisperX or a hosted recogniser); shot list (PySceneDetect, BSD-3-Clause per its [licence page](https://scenedetect.com/copyright)); silences and loudness (FFmpeg); contact sheets with burned-in timestamps |
| Ordinary project files | `TASK.md`, `sources.json`, `transcript.md` packed by phrase, `shots.csv`, `PLAN.md`, `edl.json`, `project.md`; search is `grep` |
| On-demand looking | Two small scripts: frames or a filmstrip for a span, an audio clip or waveform for a span |
| Edit as data | The agent writes an EDL; a fixed `render.py` extracts, concatenates, fades, overlays, burns subtitles last. HyperFrames or Remotion for graphics |
| Check, then look | `ffprobe` against the brief; filmstrips at each cut and caption; loudness; re-transcription of the output |
| A skill file | The procedure and the cut rules |

**browser-use/video-use** (MIT) is close to a ready-made instance: transcript always loaded, a filmstrip-plus-waveform image on demand, self-evaluation of the render at every cut boundary with up to three fix passes, session memory in `project.md`, and twelve hard rules such as never cutting inside a word ([repo](https://github.com/browser-use/video-use); [SKILL.md](https://raw.githubusercontent.com/browser-use/video-use/main/SKILL.md)). It has no published benchmark score, and its default transcription is a paid hosted service.

## 4. R02: both halves of the idea are published; the combination is not

**Finding.** Cassette-Editor is the closest prior art for a typed, undoable, revision-checked timeline harness. Its agent has two tools, a read of timeline, source ranges, rendered frames and history, and a patch submission in a language derived from the document schema. The executor derives consequences (deleting a clip closes the gap, shifts dependents, removes the dissolve); a rulebook of 110 rules rejects or repairs; commits are atomic; "a patch not based on the run's own reads of the current version is refused until the agent rereads"; undo is whole-step with branches; a user "can protect a shot from the agent"; transcripts and shot descriptions are mapped from source onto the current timeline ([Cassette-Editor](https://arxiv.org/html/2610.37690)). Its limits define what is left: perception is computed at import, not sought on demand; "no run inspected rendered video"; the projects are two 3-minute interview edits; the 31 requests are the authors' own, "in five families that probe the design decisions"; one model; no code link found in the paper.

Two of its ablations matter directly. **Replacing the open typed language with a ten-operation catalogue cut passes from 92/93 to 65/93**, with the catalogue failing every trial of eight requests its operations could not express. And "no individual intervention significantly changed its primary measure" in the main experiment; effects appeared only on requests that exercise the component (removing derived consequences: 230/232 → 199/232 on dependent clips). Detailed diagnostics saved cost, not acceptance (codes alone: 56/60 vs 58/60 at 2.44 times the cost). Against general agents on 50 TVSum videos it scored F1 23.8 vs 20.1 for Codex CLI on the same model, and was not significantly different from Claude Code with Fable 5.2 (23.1) ([Cassette-Editor](https://arxiv.org/html/2610.37690)). It establishes priority for the idea more firmly than the size of the effect.

## 5. R03, R07 and the practice side of R08: editors log takes, view everything and lock sections

Everything in this section was read as search-result snippets or summaries; no primary page was opened, Murch's book and the assistant-editor handbooks were not read, and some attributions are uncertain. Treat it as leads. It also matters less than it did: the user has set aside the logging assistant as the first build, so the Select record is no longer on the critical path.

**R03, selects and logging.** Practice organises a log around the take and its place in the script or topic: the script supervisor's lined script and circled takes ([Wikipedia, Script supervisor](https://en.wikipedia.org/wiki/Script_supervisor)), an assistant's codebook ([Jonny Elwyn](https://jonnyelwyn.co.uk/film-and-video-editing/inside-an-assistant-film-editors-codebook/)), line stringouts built from script sync ([Frame.io, Stringouts](https://workflow.frame.io/guide/stringouts)). Documentary editors work from paper edits whose quotes carry source and timecode ([Reduct](https://reduct.video/blog/paper-edits-for-documentary-filmmakers)) and from source-based and topic-based select reels ([Bricca, ch. 5](https://www.oreilly.com/library/view/documentary-editing/9781317198369/xhtml/Ch05.xhtml)). The researcher's field-by-field verdict on `Select`: `source` and `span` match; `reason` overloads three things practice separates (what the passage is, how good it is, a note); `alternates` has the right intent and the wrong shape, since practice groups by the line or setup the takes cover; `cites` has no counterpart and serves the audit trail; "approved" is stronger than anything found for a select. Missing with a practice counterpart: take identity, a rating and who gave it, what the passage covers, role and topic tags, speaker. Editors hand over a sequence that plays, so the record is the log behind a stringout, not the deliverable.

**R07, enough exploration.** The norm found is to view everything once before choosing, at a budgeted cost: Bricca puts viewing and digesting at 10–20% of editing time ([preview PDF](https://api.pageplace.de/preview/DT0400.9781000854664_A45363832/preview-9781000854664_A45363832.pdf)); Murch screens dailies and takes "very specific notes about everything" before starting ([Filmmaker Magazine](https://filmmakermagazine.com/?p=118329)). In a formative study with eight professional creators, editors said a transcript can look fine while the picture is wrong and that cut-offs and jump cuts do not show in a transcript or thumbnails ([VideoDiff](https://arxiv.org/html/2502.10190)). **No research was found on satisficing against exhaustive review in creative selection**; that is a gap in the search, not a confirmed absence. Inference: the design's rule against stopping at the first adequate candidate is supported in direction; the part that corresponds to practice is the coverage report, which should say what fraction was covered by which instrument, with full transcript coverage as the cheap tier and sampled picture coverage as the tier a stop rule governs. The experiment that settles it for agents is the fixed-budget sweep in R05 with coverage reported per instrument; no stronger design was proposed in the notes.

**R08, practice side.** The named stages are real as versions shown to someone, while the work inside them is per scene, reel and sequence, and lock is partial and reopened: a feature locked reel by reel ([Noam Kroll](https://noamkroll.com/feature-film-update-why-im-locking-my-film-reel-by-reel/)); change lists produced by comparing two cut lists ([Sound on Sound](https://www.soundonsound.com/techniques/conforming-re-conforming-pro-tools)); numbered turnovers with version bumps ([The Look](https://public.thelooklondon.com/turnover/from-editorial-to-finishing-aka-turnover)). The researcher's verdicts: a pass that belongs to a part of the cut is supported; `Decision` as the unit is too fine, practice's unit being a section at a version; **declared `depends_on` is not supported, because practice finds what a change affects by diffing two versions**; approvals tied to a revision and recorded reopening are supported; five passes are supported as vocabulary, not as a state machine; keeping stringout and rough cut apart holds for documentary and interview and not for scripted work.

One correction between notes: the editing-practice researcher could not confirm two Timeline-Bench figures the design quotes (66% of editors' notes on pacing, story or shot choice; 5.5% of agents' fixes). The two researchers who read the paper in full report both from its §6 ([Timeline-Bench §6](https://arxiv.org/html/2609.35143)), so the design's figures stand.

## 6. R04, R05, R06: transcripts carry dialogue footage, and citing alone does not make claims correct

All three sets of evidence are multiple-choice question answering. None is editing, and the researcher flags that effect sizes may not transfer.

### R04: static index against exploration

**Finding.** No published study runs transcript-only, transcript plus shot captions, dense native inference, an adaptive agent and a retrieval index on the same dialogue-led footage with all cost counted. What exists: on Video-MME's long split, Qwen2.5-VL-7B scores 40.3 with the question only, **65.4 with subtitles, 52.0 with frames, 66.0 with both**; LLaVA-Video-7B 40.9 / 64.7 / 52.4 / 67.0 ([modality study, Table 1](https://arxiv.org/html/2510.12299v1)). Exploration beats a token-matched dense pass only as videos get longer: SAVE against native at matched dollars is 66.88 vs 62.03 on Minerva, with no gain under 5 minutes (66.32 vs 67.36) and +8.8 at 15 minutes or more ([SAVE §5](https://arxiv.org/html/2611.15079v1)). A cached caption index is a cost trade: Caption-once, Frames-on-Demand scores 67.5 on Video-MME with 5.8 frames per question against 75.9 for its own reasoning model run densely ([CFD Table 3](https://arxiv.org/html/2609.11899v1)). Lazy and eager index construction differed by at most 3.1% with no consistent direction, with a weak CLIP scorer ([LazySloth §4.2](https://arxiv.org/html/2609.37426v1)). The only editing evidence is VIVID's −16.0 without on-demand inspection, which removes looking without substituting a static index ([VIVID Table 2](https://arxiv.org/html/2611.20688v1)).

### R06: citations and evidence validity

**Finding.** The evidence says traceability, with correctness gains coming from elsewhere. In ALCE a closed-book model beats the citing model on correctness on two of three datasets ([ALCE](https://arxiv.org/html/2305.14627v2)); up to 57% of citations are post-rationalised ([Wallat et al.](https://arxiv.org/html/2412.18004v1)). In video, the best model on NExT-GQA scores 69% on answers and 16% on grounded answers ([NExT-GQA](https://arxiv.org/html/2309.01327v2)), and a small study of timestamp citations concludes that "timestamps imply grounding without ensuring correctness, increasing user trust but not accuracy": asking the same vision model whether its cited frame supports the claim flagged 0 of 40 claims, while a small entailment model on a blind re-caption caught 11 of 14 fabricated claims and flagged none of 19 true ones ([citation-verifier study](https://arxiv.org/html/2608.15574v1); 40 claims, wide interval). What moves correctness is an independent check, a gate that withholds unsupported evidence ([ActiveForager](https://arxiv.org/pdf/2611.24267v2), trained model, per `docs/research.md`), or persistence of observations and task state (VIVID's −10.8, confounded). The researcher's reading: the claim taxonomy is the act of citing plus a rule-based gate; `verified` is the independent check; VIVID's memory ablation is not evidence for the taxonomy. No study toggles only "claims must cite" in a video or agent setting.

## 7. R08, R09, R10, R12: gates beat recaps, judges fail per edit, and twenty tasks decide little

### R08 and R09: structured state and regressions

**Finding.** No study compares typed state against plain files holding the same facts. Structure that only tells a strong model how to work buys little: Timeline-Bench's guidance arm was null; context files "do not generally improve task success rates, while increasing inference cost by over 20% on average" ([AGENTS.md study](https://arxiv.org/abs/2602.11988)); "a subpar plan hurts performance even more than no plan at all", and added phases hurt "when they are not aligned with the model's internal strategy" ([From Plan to Action](https://arxiv.org/html/2604.12147)). Gains attributed to state appear where the state sits outside the context, is written by the harness from checks, and is re-shown at the point of decision, and those studies compare against the bare agent, so extra calls and fresh contexts are confounded ([LongHorizon-Harness](https://arxiv.org/html/2608.01964), ablation table not read).

On regressions the code evidence is clear and the timeline evidence is absent. **40% to 73% of multi-turn programming tasks lose previously correct behaviour**; a verification gate that runs regression tests and rolls back "is the only strategy that produces large and stable mitigation gains" (tasks with regression 43.2% → 12.5% on one model), a recap of earlier requirements gives smaller gains, and the two together do not beat the gate alone ([regression study §5.3](https://arxiv.org/html/2607.01855v1)). The one direct test of maintained project state found more issues fixed and **pass-to-pass regressions up from 16 to 23** ([StateHarness](https://arxiv.org/html/2610.17616), unreviewed preprint). No study measures regressions for timeline editing agents; the design's Revise family would be the first found. Inference: an UberScene cut is a file, so "approved material disturbed" is computable exactly, which makes the strongest simple control cheap. What a gate cannot cover is an approved segment that is untouched in the file and works differently because its neighbour changed; only that residue needs dependency state or re-review, and it has no evidence either way.

### R10: render-based criticism

**Finding.** Timeline-Bench's three-judge panel tracks editors across agents (ρ = 0.93) and barely agrees with them on a single edit (κ = 0.15; one editor against the others is κ = 0.14) ([Timeline-Bench §3.3, §7](https://arxiv.org/html/2609.35143v1)). A critic's job is exactly a per-edit verdict. High agreement figures come from narrow, checkable items, such as AgenticVBench's binary rubric items at 96–98% ([AgenticVBench App. C](https://arxiv.org/html/2605.27705)); low ones come from holistic craft. **Pairwise judging is not safely better than absolute scoring**: in the one narrative-editing study, the judge picked the human edit 55.6% of the time in position A and 20.2% in position B, "a swing of 35.4 pp driven purely by presentation order" ([MEDit-Bench App. E](https://arxiv.org/html/2607.25300v1)). Critic loops help when feedback is external, grounded and executable and are flat or harmful when a prompted model critiques its own family's work ([self-correction survey](https://arxiv.org/abs/2406.01297), abstract only); in video editing the measured gains are modest or mixed, and no critic has a published false-accept rate (`docs/research-editing.md`). No watching-versus-reading comparison with the same critic exists, so H4 stays open.

### Deliverable: the minimal bridge protocol

One long-lived Node process, JSON lines on stdin and stdout, every reply carrying `revision`. The revision is a SHA-256 over the bytes of `video.tsx`, the path and bytes of each module `gatherLocalFiles` returns (sorted), and the manifest bytes; UberScene commit, Chrome build, `--props` and `--import` are recorded beside it.

| Command | In | Out |
| --- | --- | --- |
| `open` | file, manifest | revision, errors, elements |
| `state` | — | revision, composition, tracks, elements, errors |
| `actions` | element id | kind, editable, props as literal, bound or locked, action names |
| `apply` with `dry_run` | expected revision, actions | ok, errors (through `can()` on one `batch/apply`) |
| `apply` | expected revision, actions, label | ok, new revision, round, text diff, baked, errors |
| `undo` | expected revision, round | restores the stored text of the round before |
| `reload` | — | as `open`, after the agent edited the text |

The commit runs in seven steps: re-read the files and refuse with `STALE_REVISION` unless the disk revision equals both the expected one and the one the executor was loaded from; execute one `batch/apply`; fold, and treat a non-empty `skipped` or a throw as `FOLD_FAILED`; load the folded text in memory and compare its timeline and errors with the executor's state, returning `FOLD_MISMATCH` on a difference; re-check the disk revision and write through a temporary file and rename; store the previous and new text under the round number and reset the executor; return the new revision and diff. Undo is a text restore, last round first, because it is exact, survives a new process and covers bakes and the agent's own text edits. UberScene's tests already cover most of M0's bridge item, so M0 needs to prove only what UberScene lacks: the revision check, fresh-process undo and the JSON boundary.

Against that, +8.8 at 15 minutes or more and VIVID's −16.0 without inspection, which had no static-index arm |
| Claim taxonomy | Citations improve traceability but not correctness or downstream editing | **Leaning toward met**; met by published evidence for text and video question answering, untested in editing agents | [ALCE](https://arxiv.org/html/2305.14627v2); [Wallat et al.](https://arxiv.org/html/2412.18004v1); [citation-verifier study](https://arxiv.org/html/2608.15574v1). The researcher expects the taxonomy to "pass on traceability and probably fail on correctness unless it is paired with a gate or an independent check" |
| Activity prior | Uniform or transcript-guided selection performs equally well | **Open** | No published test of a bitrate or audio-energy prior. Scorer-based selectors do not reliably beat uniform ([APS Table 1](https://arxiv.org/html/2611.24079)), but the prior's near-zero cost makes its test clean |
| Editorial pass state | Ordinary project files and procedural prompts perform equally well | **Leaning toward met** | Guidance null on Timeline-Bench; context files add cost without success; misaligned phases hurt; richer state raised regressions once; practice uses versioned sections and computed diffs. No typed-versus-file study exists. The gate and revision check are the evidenced part |
| Automated critic | It introduces regressions or gives no advantage over simpler checks | **Open, leaning against craft scoring** | κ = 0.15 per edit; 35-point order swing for a pairwise judge; loops flat without external feedback. No false-accept rate and no watching-versus-reading test published. Computed cut rate and static hold are an untested "simpler check" |
| Dedicated benchmark | Existing tasks can answer the question without confounds | **Met for whole-harness lift; open for the rest** | AgenticVBench and Timeline-Bench answer "does the harness help". Neither holds the edit path constant or scores revision; the Revise and injected-defect families have no external substitute found |

## 11. What is still novel, narrowly

After Cassette-Editor, RefineCut, Cutible, VIVID and Timeline-Bench's container, the defensible claims are these, in the researcher's order of strength, all subject to the limits of a one-day search.

**The 2×2 on one model.** Perception tools on or off × typed timeline against FFmpeg, on AgenticVBench or Timeline-Bench. VIVID fills one column and Cassette-Editor one row of a different table; nobody has the four cells on long raw sources. It is design.md section 8.3's second row turned around: hold the perception tools fixed and vary the edit path.

**Typed actions against free-form video code against FFmpeg, at matched budget.** Agents can already write Remotion or HyperFrames code on Timeline-Bench, so the open question is whether a closed, typed, undoable action layer over a code file beats letting the agent write the code. UberScene's own skill tells agents to edit the TSX as text; that is the baseline the bridge must beat, and it is the fairest one because it shares UberScene's renderer, lint and `look`. **The warning points the other way: a closed operation catalogue cut Cassette-Editor's passes from 92 to 65 of 93.** UberScene's 95 actions are far more than ten, but the same test applies, and the bridge needs a text-edit escape hatch covered by the same revision check. If Timeline-Bench reports results by toolkit, which was not checked, this claim shrinks.

**A critic that watches and hears against one that reads.** Auto-Director reviews keyframes, EditDuet reads text, Cassette-Editor checks structure, and Timeline-Bench shows agents review stills. An audiovisual critic compared with a timeline-reading one, with fixes constrained to actions that pass a dry run, is unpublished in what was searched. The prior for craft verdicts is poor, so the novel result may well be a negative one.

Smaller: approvals with dependencies as state (nearest are Cassette-Editor's protected shots and Nath et al.'s "locked spine"); kind-specific eligibility rules in editing (VideoNexus already attaches an evidence status to claims in question answering); a redistributable set that scores finding apart from editing; and the first regression-rate measurement for timeline agents under revision. Cheap re-rendering was not found as a claim in any paper; it is an engineering property whose research value would be making review after every edit affordable, which matters because Timeline-Bench agents first render 72–90% of the way through a run. That link is a hypothesis.

## 12. Detectable differences: twenty tasks see only large effects

The table below is **the researcher's own arithmetic, not a published result**: normal approximation, two-sided α = 0.05, 80% power, a paired difference between two arms on the same n tasks with k runs each, binary outcome, and worst-case run noise (every task at a 25% success rate, no treatment heterogeneity). The minimum detectable difference is about 2.8 standard errors.

| Tasks | Runs per task | Standard error | Detectable difference |
| --- | --- | --- | --- |
| 56 | 1 | 0.082 | 23 points |
| 56 | 5 | 0.037 | 10 points |
| 56 | 10 | 0.026 | 7 points |
| 20 | 1 | 0.137 | 38 points |
| 20 | 5 | 0.061 | 17 points |
| 20 | 10 | 0.043 | 12 points |
| 100 | 3 | 0.035 | 10 points |

Detecting an effect the size of Timeline-Bench's guidance arm (15 vs 12 of 56, 5.4 points) needs about **1,000 task-runs per arm** under the same assumptions, for example 56 tasks × 18 runs. For a continuous paired outcome, about 32 source-task pairs detect a standardised effect of 0.5 and 88 detect 0.3. The assumptions err both ways: tasks that share a source are not independent, which can enlarge standard errors up to threefold in Miller's example, while tasks that always fail or always pass (35 of Timeline-Bench's 56 were resolved by no agent) carry less run noise, so more tasks matter more than more runs. **No run-to-run variance for video-editing agents has been published**, so a pilot of about 10 tasks × 5 runs per arm must replace the assumed variance before any size is fixed. For scale, VIVID's +20 points would be visible at 56 × 5; a typed-timeline effect of a few points would not.

## 13. Changes to design.md

### (a) Correct now: facts the design gets wrong

1. **Action count.** UberScene has 95 actions, 12 of them inverse-only, about 83 forward. "98" in UberScene's docs is stale.
2. **Undo.** Section 6.1's `undo` "backed by `invert`, the patch log" is wrong for a bridge. Undo must be a restore of the stored file version for that round, last round first.
3. **Commit.** A fold can report `skipped` edits or throw after `execute()` returned ok, and `BREAKS_FILE` is checked on the in-memory state. A commit needs reload-and-compare before the write.
4. **Parameter ranges.** `affordances()` returns none. Section 6.1's `actions(element)` must take ranges from the kit's schemas or drop the promise. Actions that create something are never listed by `affordances()`.
5. **Render identity.** Byte-identical renders are the wrong test. Keep the file hash as an identity; compare decoded pictures within a stated tolerance, per configuration (tabs, GPU, codec mode). M0's "compare frame hashes" changes accordingly. Untested: nothing was rendered.
6. **Frame cache.** It feeds only `look` and `--still`, never an export, and its key omits media content, codec mode, GPU, exact Chrome build and UberScene's code when the version string is unchanged. The real risk is a cached `look` sheet disagreeing with a fresh render. Clear the cache whenever the UberScene pin moves.
7. **Shots and silences.** Nothing in UberScene produces them. Section 5.2's "from UberScene's manifest" must become "UberLens computes them and writes them into the manifest".
8. **Word anchors.** `word:N` is an index into one version of one transcript; replacing the transcript renumbers words silently. Store the transcript's content hash beside every anchor. UberScene's transcript has no confidence field, so word confidence lives in UberLens's own store.
9. **Exit codes.** The CLI exits 0 on resolve errors, including for a render of a broken file. `check` reads error rows, not exit codes.
10. **`look` size.** It fails above 64 cells; UberLens must page with `--at`.
11. **SDK release.** `@uberscene/sdk`, `can()` and `affordances()` exist on `main` and appear unreleased (registry not checked). M0 starts with "pin and build UberScene from a commit".
12. **Project revision scope.** Add the file's own modules and note that a manifest can be exported from inside the file.
13. **"Required by the code."** The bridge is one of two ways to edit. UberScene's skill edits the TSX as text; say that this is the baseline.
14. **"It never writes FFmpeg commands."** UberScene has no audio restoration, loudness normalisation, stabilisation or pitch-preserving speed change. State the mixed mode.
15. **"Ours."** The expected-revision check is prior art (Cassette-Editor). The critic fix validated against available actions is partly prior art (its typed repair options). "Ground truth from code because the video is a file" is shared with Cassette-Editor and TimelineBench. Remove or qualify the marks.
16. **"The editing papers build their machinery on FFmpeg commands."** True of VIVID and of the 2025 to mid-2026 papers; no longer true of the field as of October 2026. Cite Cassette-Editor, RefineCut and Cutible in section 1 and answer open question 4 with "none found, not specifically searched".
17. **Open licences.** AgentVidBench is not all openly licensed: 4 of its 71 videos are CC BY-NC and 6 are share-alike; MMTB has non-commercial and GPL items. Section 12 can strike AgenticVBench's repository from "unverified" (Apache-2.0); its media terms remain unverified.
18. **Pairwise judging.** Section 6.3 treats pairwise comparison as the likely better signal. It is not safely better than absolute scores: require both orders and count only order-consistent wins.
19. **Render cost.** Add the measured figure from UberScene's docs (about 6 frames a second at 1080p on four cores for a file with three.js), and that a draft is a different file whose approval does not carry to the final. Three critic rounds on a one-minute cut is of the order of a quarter of an hour of rendering.
20. **Section 1's Timeline-Bench reading.** Add that Timeline-Bench's container already ships Remotion and HyperFrames, so its craft failures occurred with video-as-code available.

### (b) Simplify or demote

1. **Claim kinds and eligibility** leave the agent's loop. Keep harness-written observations as a log with plain citations, and add an independent check of cited payloads (a second model family, or entailment on a blind re-description). Kind-based eligibility and required verdicts return only if the R06 experiment shows a correctness gain.
2. **Global and per-decision pass state** become versioned sections: a part of the cut at a version, an approval tied to that version and to who it is for, notes keyed to a revision and a time range. Drop `depends_on`; compute what a change affects by diffing two revisions.
3. **A code gate with rollback on approved ranges** replaces `keep` lists and Decision records as the protection against regressions, alongside the expected-revision check, which now also covers the agent's text edits.
4. **Frame count is set by the harness from span width.** Agent-set burst interval and density become the variant under test.
5. **Passes are vocabulary**, carried in a guide file as prose. Pass-dependent tool behaviour is built only if the R08 experiment shows it wins against files plus prose.
6. **The activity prior and the belief scheduler stay experiments**; the overview defaults to uniform or transcript-guided placement until R05 says otherwise.
7. **The critic** asks yes/no questions tied to the segment's stated purpose, runs after code checks that include computed cut rate and longest static hold, and comes from a different model family. The 1–5 craft score is dropped as a decision input.
8. **The benchmark** shrinks from seven families of about 20 tasks to adapters for AgenticVBench and Timeline-Bench plus a Revise family and an injected-defect family, with one pre-registered contrast at 50 or more tasks.
9. **The Select record** is demoted to a log behind a playable sequence; if kept, it gains a coverage key (the line or topic it covers), a rating with its author, and a speaker.
10. **Section 10's first experiment** (interview selects, three agents, editors) is no longer the first build under the user's direction; it is replaced by the plan below. The transcript-first baseline it defined is kept as Agent A everywhere.

### (c) The experiment plan, in order

Every experiment uses the same named baselines. **The honest baseline:** a prepared transcript and shot index handed to a coding agent with a skill, for example video-use. **UberScene text:** the agent edits `video.tsx` as text with UberScene's own skill. **VIVID:** installed as published. Every arm gets the same information as plain text, matched budgets with ingest charged, several runs per task, and inference on per-task differences clustered by source.

1. **M0 preconditions, not an experiment.** Pin and build UberScene; run the seven-step commit, fresh-process text undo and stale-revision refusal; render one file twice per configuration and record equality within tolerance; time a render on the target machine; read the dataset cards and Timeline-Bench's access terms.
2. **Variance pilot and baseline check: the cheapest decisive experiment.** About 10 AgenticVBench tasks × 5 runs, one model, three arms: native agent, the honest baseline, VIVID. It replaces the assumed variance in section 12 with a measured one, and it tests the most important untested claim: whether a transcript and shot index built before the clock starts removes most of the gap VIVID closes. If the honest baseline lands near VIVID, the perception half of UberLens is a preparation script and a skill.
3. **Edit path at fixed perception.** The same prepared perception in every arm; edit by agent-written FFmpeg, by UberScene text, or by the typed bridge with a text escape hatch. Finishing-heavy tasks first (captions, titles, reframing), since that is where the evidence for a structured timeline is. Primary outcome is the benchmark's own score; the secondary is the time of first look at the cut, to test whether cheap looking moves review earlier. Stop building the bridge if typed actions do not beat UberScene text at matched budget.
4. **The full 2×2**, perception tools off or on × FFmpeg or the winning UberScene arm, on the whole of AgenticVBench at the size the pilot says is needed, and on Timeline-Bench if access is granted. This is the publishable result.
5. **Critic detection by injected defects.** Scored by code, about 100 injected and 100 clean segments per defect family; the watching critic, the reading critic and the code checks alone. Cheap because injection is by known UberScene actions. It settles the detection half of H4 before any human rating is bought.
6. **Revise 2×2: state × gate.** Plain files or typed records, gate off or on, about 30–40 revision tasks × 5 runs, scored by code on approved material disturbed.
7. **Citations, four arms** (R06), on items with labelled evidence spans including absent-evidence items.
8. **Index against exploration, and adaptive against uniform** (R04, R05), on dialogue-led footage with fixed strata; needs in-house annotation, so it comes late.
9. **Passes against files plus prose, and critic improvement** (R08, R10b), last because both need blind editors at about 50 tasks × 3 runs.

This order differs from the priority sequence in `_tasks.md` (R01 → R04 → R06 → R08 → R12) in one respect: R01's baseline still comes first and R12's method applies throughout, but the edit-path experiment, which comes out of R02 and R13, moves ahead of R04 because the user's direction makes the edit path, not exploration on interviews, the thing that distinguishes UberLens.

## Conclusion

The research shifts where UberLens's risk sits. Before it, the open question was whether the evidence machinery helps an agent find things; the literature now gives a fairly confident prior that citing and classifying claims will buy traceability and little else, and that a transcript built at ingest covers most dialogue footage. The larger and less examined bet is the one the user has chosen: that an agent edits better through a typed code timeline than through FFmpeg or through freely written video code. That bet has one paper for it, with a self-built evaluation, one ablation in the same paper warning that closed vocabularies cost expressiveness, and a benchmark on which video-as-code was available and agents still failed on craft. A three-arm edit-path run at fixed perception is small, uses existing benchmarks, and returns a useful answer either way: a win is the first controlled result for typed timeline editing on long sources, and a loss says UberScene's value to agents is its renderer, lint and `look`, used through plain text edits, with far less of UberLens to build.

Two things would change this picture and were out of reach: whether Timeline-Bench reports results by toolkit, and what TimelineBench (NeurIPS 2026) and RefineCut actually tested. Both should be read before the 2×2 is described anywhere as unpublished.
